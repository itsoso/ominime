# OmniMe 安全与采集链路收敛设计

## 目标

在不破坏历史输入数据的前提下，修复本地 Web 数据暴露、跨应用误归属、EventTap 回调截图、AI 失败递归和错误路由；删除没有实际图像输入的 Qwen-VL 上下文分析；收敛安装、依赖和隐私语义。

## 方案比较

### 方案 A：分阶段收敛（采用）

先修安全和正确性，再删除伪多模态与高风险 OCR 路径，最后清理部署和死代码。每一阶段保留现有测试并增加回归测试，历史数据库先兼容读取，不立即重建表。

优点是风险可控、可逐步验证；缺点是数据库会暂时保留部分废弃列。

### 方案 B：完整重写采集器

重新设计 EventTap、AX 和持久化状态机。最终结构可能更整洁，但一次性替换 2,000 多行高风险原生代码，难以证明没有输入回归，本轮不采用。

### 方案 C：仅关闭配置

继续保留 Qwen-VL、OCR 和开放 API，只把相关开关设为关闭。改动最小，但误导代码、资源风险和可被重新开启的安全问题仍然存在，本轮不采用。

## 架构边界

目标采集链路为：EventTap 仅采样事件和目标应用身份；worker 对目标 PID 做最小 AX 查询；先执行 ignored/secure/count-only 策略；有可信 AXValue 才保存文本，否则只保存计数和诊断。

Kim/微信整窗 Vision OCR 从默认路径移除。豆包候选推演不再参与可信文本保存；如果后续确有业务价值，应以独立、可观测、默认关闭的实验重新引入，而不是继续嵌入 EventTap。

Qwen-VL per-submission 分析完整移除：不再创建后台线程，不再加载模型，不再产生 Qwen 状态。历史 `submission_contexts` 数据和旧列暂时保留，API 不再暴露模型输出；后续通过显式数据库迁移清理。

## Web 与隐私

Web 服务默认并强制监听 loopback。中间件拒绝非本机 Host 和跨站 Origin，不使用通配 CORS。所有动态页面内容进行 HTML 转义，敏感接口保持同源访问。

OpenAI 不再因环境中存在 API Key 而自动启用。远程 AI 必须显式开启，界面准确说明内容可能离开本机；页面依赖改成本地静态资源或系统字体。

数据目录和敏感文件在启动时收紧权限。保留策略先提供配置和安全清理入口，不静默删除历史数据。

## 统计与错误处理

不再把每次 Enter 人为折算为一分钟活跃时间。无法从现有事件可靠推导的效率和深度工作指标从主要界面移除或标记为不可用。

AI 失败直接回退到纯规则总结，不能再次进入 AI 分支。同步数据库/模型操作不阻塞 FastAPI 事件循环。后台采集异常必须进入 runtime diagnostics，不能只在 debug 模式静默吞掉。

## 部署与维护

统一 Python 依赖元数据和唯一 LaunchAgent 安装入口，安装不得再次手工启动第二实例。测试仅从 `tests/` 收集，真实 LLM 检查脚本改为显式命令并禁止打印 Key 片段。

删除由本次收敛确认无生产调用的 Qwen、截图范围、AppTracker 和 legacy 菜单残留；`keyboard_listener.py` 仅做必要拆分，不进行大爆炸式重写。

## 验证标准

- 恶意 Origin 和非本机 Host 无法读取输入 API。
- Enter 后快速切换应用不会读取另一个 PID 的 AXValue。
- EventTap callback 不执行 CGWindow 截图。
- 仓库无 Qwen-VL 运行时引用，保存提交不会创建分析线程。
- AI 后端失败可稳定返回规则总结。
- `/api/report/full` 返回有效报告而不是日期格式 400。
- 安装后的运行依赖完整且只启动一个 app 实例。
- 全量 pytest、编译检查和本地 API smoke test 通过。
