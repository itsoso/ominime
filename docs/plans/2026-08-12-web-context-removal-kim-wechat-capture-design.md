# Web 上下文移除与 Kim/微信正文采集设计

## 目标

删除 Web 控制页中的上下文入口和相关 API，停止为新提交写入上下文记录，同时保留历史数据库表与历史数据。恢复 Kim 和微信在辅助功能无法提供输入框正文时的本机正文采集，但不恢复多模态分析、远程分析或 EventTap 回调截图。

## 现状与根因

Web 模板仍包含“上下文”标签页、上下文卡片样式和 `/api/submissions` 请求逻辑，后端也继续暴露该接口并在健康信息中返回上下文开关。

Kim 和微信现有提交诊断持续显示 `degraded_count_unreadable`。仓库中已有针对两者输入框区域的 macOS Vision OCR 实现，但生产 `KeyboardListener` 不再构造对应采集器，且 worker 没有在 Enter 时生成预提交帧，因此识别分支在生产环境不可达。

## 方案比较

### 方案 A：AX 优先，worker 内局部 OCR 回退（采用）

正常应用和可读输入框继续优先使用目标 PID 的 AXValue。Kim/微信的 AXValue 不可用或为空时，由事件 worker 对已预备的目标窗口生成一次图像，并仅识别固定的输入框 ROI。图像只存在于内存，不保存、不发送给模型、不离开本机。

优点是复用现有、已有较完整测试的本机识别器，同时避免在 EventTap 回调中执行截图。缺点是依赖窗口布局，布局变化时会安全降级为字符计数并留下诊断。

### 方案 B：持续轮询 AX

定期读取 Kim/微信辅助功能树并尝试拼接内容。它不需要图像，但现有运行证据表明两者经常没有可用的焦点元素或 AXValue；持续轮询还会增加原生调用与状态同步复杂度。

### 方案 C：EventTap 回调中截图

在 Enter 原生回调内立即截图，可更接近按键时刻，但会延长系统事件回调，增加事件超时、卡顿和崩溃风险，因此不采用。

## Web 与持久化边界

- 删除 Web 的上下文标签、上下文卡片样式、加载和渲染函数。
- 删除 `/api/submissions` 路由。
- `/api/health` 不再暴露 `capture_context_on_enter`。
- 新提交不再调用 `save_submission_context()`，只保存输入正文和不含窗口、控件层级等上下文详情的采集诊断。
- 历史 `submission_contexts` 表、数据库方法和既有行暂时保留，避免破坏性迁移；运行时不再新增记录，Web 也无法读取它们。

## Kim/微信采集数据流

1. EventTap 回调采样按键、目标 PID 和应用身份；仅对身份已验证的 Kim/微信无修饰 Enter，从已预备窗口复制一次内存图像后入队。
2. worker 在 Kim/微信普通输入按键期间预备目标窗口 ID；不读取像素。
3. worker 收到 Enter 后，提交流程依次尝试可信 AXValue、输入法候选/键盘文本和本机 ROI OCR。
5. OCR 文本必须通过输入法状态、边缘裁切、单行约束和物理按键数量校验后才能保存。
6. 识别失败时只保存字符数和失败码，不保存图像或不可信文本。

## 安全与错误处理

- secure text 不执行 OCR；忽略应用、Shift/Alt Enter、Command/Control Enter 不复制图像也不执行 OCR。
- EventTap callback 只复制已预备、PID 与身份完全匹配的窗口图像；不枚举窗口、不运行 Vision、不读取输入法 API。Vision 识别只在 worker 中执行。
- OCR 类在生产监听器中显式构造，导入或原生调用失败必须通过既有诊断路径体现，不能伪造成功。
- 图像不进入事件持久化字段、日志、数据库或 AI 分析。

## 验证标准

- Web 模板中不存在上下文标签、卡片、加载函数或 `/api/submissions` 请求。
- `/api/submissions` 返回 404，健康接口不含上下文配置。
- 新提交不会新增 `submission_contexts` 行；输入正文仍会写入 `input_records`。
- 默认生产监听器拥有 Kim 和微信本机采集器。
- Kim/微信 AX 不可用时，worker 生成输入框帧并可保存通过校验的 OCR 正文。
- AX 正文、输入法候选等更可信来源优先于 OCR。
- secure/忽略/快捷键路径不截图；OCR 失败安全降级并写诊断。
- 全量测试、静态检查、服务重启和本机 Web/API smoke test 通过。
