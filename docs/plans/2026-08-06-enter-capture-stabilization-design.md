# Enter 捕获稳定化设计

日期：2026-08-06
读者：普通使用者与维护者
状态：已批准实施

## 目标

让 OmniMe 在不干扰正常输入的前提下，只保存用户明确提交的文本；当系统无法可信地读取内容时，宁可只记诊断，也不抓取整页、整篇文档或密码。

## 当前问题

- EventTap 回调中会同步访问辅助功能树，剪贴板兜底还会等待，容易触发系统超时并禁用监听。
- 同一个物理 Enter 的 keyDown 与 keyUp 可能各自走一遍捕获流程，产生重复工作或重复诊断。
- 通用 `Cmd+A` / `Cmd+C` 会改变选择状态，并可能复制整页内容。
- `AXValue` 缺少隐私与尺寸门禁，焦点识别失败时容易把容器或文档值当成输入框。
- 菜单栏把“已保存字符”和“跳过时估算的按键数”混成一个数字。
- App 与独立 Web 进程各自保存运行状态，且可能同时争用同一个端口。

## 设计

### 1. EventTap 只做快速采样

回调只提取事件类型、键码、修饰键、目标应用和键盘文本，随后把不可变事件放入队列并立即返回。辅助功能读取、候选判断、诊断和保存都在工作线程执行。

### 2. 一个物理 Enter 对应一个提交尝试

keyDown 创建并完成一次提交尝试；紧随其后的 keyUp 只用于结束同一次尝试，不再重新读取内容。若环境只提供 keyUp，仍允许它独立完成一次尝试。

`Shift+Enter`、`Option+Enter` 等换行组合键不视为提交。`Command` 与 `Control` 组合键继续跳过。

### 3. 候选必须经过统一门禁

候选带有来源、文本、字段身份、置信度和拒绝原因。保存前依次检查：

1. 焦点是否可确认是文本输入控件；
2. 是否为安全输入或受保护内容；
3. 是否超过可信提交文本上限；
4. 来源是否被允许；
5. 是否与本次字段和提交尝试相符。

辅助功能状态为 `degraded` 与明确的“非文本控件”分开记录，避免把权限或读取失败误报为用户焦点错误。

### 4. 关闭通用剪贴板兜底

默认捕获链路不再发送 `Cmd+A` / `Cmd+C`。未来若某个应用确实需要剪贴板，只能通过明确的应用适配器启用，并限制字段、文本尺寸和恢复行为。

### 5. 字段级缓存

最近文本和按键兜底按字段身份隔离。字段身份优先使用进程、窗口和辅助功能标识符；缺少标识符时使用控件 frame 的稳定表示。切换字段后不能复用上一输入框的文本。

### 6. 统计与状态

- 菜单栏展示“已保存字符”，跳过诊断中的物理按键数不再混入。
- 运行状态通过带时间戳和进程号的共享状态文件供 App 与 Web 读取；过期心跳显示为未知。
- App 启动内置 Web 服务前先检查端口是否已有健康服务，避免两个服务反复抢占。

## 验收标准

- EventTap 回调路径不执行辅助功能遍历、剪贴板操作或等待。
- 每个物理 Enter 最多产生一个最终捕获决策。
- `Shift+Enter`、安全输入框、非文本控件和超大 `AXValue` 不保存文本。
- 通用剪贴板兜底不可达。
- 字段切换后不会提交上一字段的缓存。
- 菜单栏字符数只统计实际保存的字符。
- 独立 Web 进程能读到 App 的新鲜录制状态，且已有 Web 服务时 App 不重复绑定端口。
